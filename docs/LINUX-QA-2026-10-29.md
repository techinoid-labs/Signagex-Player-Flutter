## Findings addressed in packaging

Without the VA/VDPAU runtime libraries, the v15-derived test segfaulted in
`mdk.vdec0`; GDB captured a null call from libmdk. Adding libva2, libva-drm2,
libva-x11-2 and libvdpau1 allowed playback to progress. scrot was also absent.
Debian now declares these dependencies; AppImage collects them explicitly
because dlopen dependencies and Imlib2 image writers evade ordinary ELF scanning.

A second crash family was observed in CrBrowserMain/libflutter, first in the
v15-derived package and again with the complete v21 runtime. It has not been
conclusively attributed to trimming or fixed by a specific change. The latter
kernel entry records CrBrowserMain[12058], SIGSEGV at c8, engine offset 44769c.
Do not claim that adding video dependencies fixed this separate failure.
Short successful tests are not a substitute for a long transition soak.

The v15-derived offline pairing retry path restarted the app. The current
branch already retains cached playback on pairing-server failure; the complete
v21 offline test exercised that implementation instead of assuming the older
binary contained it.
